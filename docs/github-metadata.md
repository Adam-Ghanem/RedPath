# GitHub metadata checklist

These repository settings are deliberately listed here because they require a maintainer’s GitHub UI access. Complete them after the `assets/social-preview.png` asset is present on the default branch.

| Setting | Recommended value | Where to set it |
| --- | --- | --- |
| Description | `Visualize Active Directory attack paths, map them to MITRE ATT&CK coverage, and expose detection gaps in a safe synthetic SOC demo.` | Repository **About** → edit description |
| Website | `https://redpath-sec.vercel.app` | Repository **About** → Website |
| Topics | `cybersecurity`, `purple-team`, `mitre-attack`, `pentest-tools`, `fastapi`, `react`, `attack-path-analysis`, `security-automation`, `soc` | Repository **About** → Topics |
| Social preview | Upload `assets/social-preview.png` | Repository **Settings** → General → Social preview |

The recommended description is concise, keyword-rich, and stays within GitHub’s 160-character description limit. After saving the social image, use GitHub’s preview to confirm that the red-fang mark and the “See the path. Prove the gap.” tagline remain readable in a link card.

> Do not manually mark the repository’s demo data as real customer telemetry. The image, website, description, and topics should consistently communicate that RedPath is a safe, synthetic evaluation environment.
